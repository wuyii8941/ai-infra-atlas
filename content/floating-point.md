## 一个数为什么存不精确
浮点数用符号、指数和有限尾数近似实数。FP32 有8位指数、23位显式尾数；FP16 是5与10；BF16 是8与7。BF16 的指数范围接近 FP32，但有效精度更粗。它不是“更精确的FP16”。

以1附近的正规数为例，BF16相邻值间距约 $2^{-7}$，FP16约 $2^{-10}$。在1附近增加0.001，是否能保留，取决于格式、舍入方式和当前值；绝不能把BF16普通误差上界统一写成 $10^{-6}$。

## 不结合律与 FMA
实数里 $(a+b)+c=a+(b+c)$；浮点运算每一步都要舍入。取FP32的 $a=10^{20},b=-10^{20},c=3$，左式可得3，右式可能得0，因为b+c的小增量丢失。

FMA将ab+c作为一个融合运算，在乘加后一次舍入；分离乘法与加法通常有两次舍入。FMA往往更接近实数结果，却不保证更接近某个固定参考执行路径。性能与数值契约需要分别确认。

## accumulation dtype 与 storage dtype
BF16输入可以提升到FP32求和，再写回BF16。这样提高中间精度，但最终输出仍被低精度存储量化。把BF16梯度转换为FP32再通信，也不能找回生成BF16梯度时已经丢失的位。

QK Fusion 保留若干低精度cast边界；Triton AdamW的rounded路径处理beta补数、除法与FMA。两者都是保持参考执行语义的工程选择，不是所有输入逐位一致的数学证明。

## 四种不同现象
**舍入差异**：同一数学计算，不同执行顺序。**算法近似**：如exact GeLU变成tanh近似，函数本身改变。**实现错误**：stride、mask、漏项等破坏语义。**非确定性**：相同输入重复执行也可能因并发归约顺序不同而变化。差分出现异常后，要分辨是哪一种。

量化是有意的近似表示，必须有质量评价；“argmax在几个输入相同”不能证明所有生成轨迹相同。

## 可运行检查
```python
import numpy as np
a, b, c = map(np.float32, [1e20, -1e20, 3.0])
print((a+b)+c, a+(b+c))
print(np.spacing(np.float32(1.0)))
print(np.spacing(np.float16(1.0)))
```
